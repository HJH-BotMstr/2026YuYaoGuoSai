## 1. 背景与目标

### 1.1 比赛背景

本赛项模拟工业巡检场景，要求四足机器人自主完成避障、巡检识别、长条抓取三类任务。比赛采用线下挑战 + 技术文档形式，最终得分 = 线下挑战（60%）+ 技术文档（40%）。

### 1.2 项目目标

在现有硬件条件下，以**稳定、鲁棒、可维护**为首要目标，完成可得分任务：

1. 避障任务：自主穿越障碍区。
2. 巡检识别任务：识别两个配电柜/变压器上的 A/B/C/D 区域字母及仪表盘状态，并完成语音播报。

长条抓取任务因未配置机械臂，本方案不纳入实施范围，但保留后续扩展接口。

### 1.3 成功指标

| 指标 | 目标值 | 验收方式 |
|------|--------|----------|
| 避障成功率 | ≥ 80%（10 次测试中 8 次无碰撞通过） | 真实场地重复测试 |
| 仪表盘状态识别准确率 | ≥ 85% | 室内模拟 20 次测试 |
| 区域字母识别准确率 | ≥ 85% | 室内模拟 20 次测试 |
| 完整流程成功率 | ≥ 70%（从出发到两次巡检播报完成） | 真实场地 10 次测试 |
| 平均单轮用时 | ≤ 3 分钟 | 计时测试 |

### 2.2 可得分数评估

当前硬件无机械臂，**理论最高可得分数为 50 分**：

- 避障任务：10 分
- 巡检识别任务：40 分（4 次识别 × 10 分）

长条抓取任务 50 分因硬件缺失放弃。

### 2.3 扣分风险规避

- **碰撞道具**：避障闭环必须保证至少 0.5m 安全距离，速度不宜过快。
- **失控冲撞**：任何异常必须触发紧急停止并趴下，不可让旧速度指令持续发送。

## 3. 总体控制策略

### 3.1 设计原则

1. **整体开环**：上层状态顺序固定，不依赖全局定位，降低系统复杂度。
2. **局部闭环**：每个状态内部基于传感器反馈实时调整速度、航向，保证对齐与避障精度。
3. **稳定优先**：宁可慢，也要保证每次都能完成核心任务。
4. **简洁可维护**：文件结构扁平，模块职责单一，便于赛前快速调试。

### 3.2 状态机总览

```
INIT
  ↓ 初始化完成
CROSS_OBSTACLE
  ↓ 到达检测区或超时
SEARCH_CABINET
  ↓ 检测到有效柜子
ALIGN_CABINET
  ↓ 横向居中且距离合适
INSPECT
  ↓ 识别稳定并播报完成
  ↓ 若未完成全部 4 次识别，返回 SEARCH_CABINET
FINISH
  ↓ 趴下、释放控制
EMERGENCY_STOP（任何状态异常时进入）
```

### 3.3 状态说明

| 状态 | 职责 | 退出条件 |
|------|------|----------|
| `INIT` | 机械狗回零、起立、切换移动模式、抢占自主控制权、启动心跳 | 初始化完成 |
| `CROSS_OBSTACLE` | 以中速直线穿越障碍区，遇锥桶向空旷侧绕行 | 深度相机判断到达检测区边界，或超时 60s |
| `SEARCH_CABINET` | 原地或低速转动搜索 A/B/C/D 字母标识 | 连续 N 帧检测到字母且置信度达标 |
| `ALIGN_CABINET` | 根据字母/仪表盘在画面中的横向位置调整航向，根据深度调整距离 | 目标横向居中、深度距离 0.8~1.2m |
| `INSPECT` | 稳定识别仪表盘状态与区域字母，触发语音播报 | 单次识别稳定并播报完成 |
| `FINISH` | 停止、趴下、释放控制权 | 完成 |
| `EMERGENCY_STOP` | 任何异常触发，清零速度、趴下、等待人工恢复 | 人工复位 |

### 4.2 数据流

1. 相机图像流入 `gauge_detector` 与 `letter_detector`。
2. 深度图流入 `mission_control_node` 的避障与对齐模块。
3. `mission_control_node` 订阅识别结果与距离信息，决策后发布 `cmd_vel`、`cmd_gait`。
4. `mission_control_node` 在识别稳定时发布语音文本到 `/voice/play`。
5. `voice_broadcast_node` 订阅 `/voice/play`，调用系统音频播放。

## 5. 感知模块设计

### 5.1 仪表盘识别

**复用模块**：[src/detect/](src/detect/)

| 文件 | 用途 | 部署建议 |
|------|------|----------|
| [realtime_gauge.cpp](src/detect/realtime_gauge.cpp) | C++ 实时仪表盘识别，性能最优 | **Lite3 部署首选**，需重新编译 |
| [realtime_gauge.py](src/detect/realtime_gauge.py) | Python 实时版本，带 3 帧稳定滤波 | 调参与原型验证 |
| [step1_hough_circle.py](src/detect/step1_hough_circle.py) | 生产级圆盘检测 | 用于离线评估圆检测参数 |
| [step2_pointer_detect.py](src/detect/step2_pointer_detect.py) | 指针检测 | 用于离线评估指针参数 |
| [rect_detect.py](src/detect/rect_detect.py) | 旋转矩形标识检测 | 确定表盘“上方”参考方向 |
| [gauge_recognition.py](src/detect/gauge_recognition.py) | 完整离线 pipeline | 高精度标定 |

**输出接口**：

```yaml
# /gauge/status
std_msgs/String
# 取值："仪表盘正常，状态良好" / "仪表盘偏高，状态异常" / "仪表盘偏低，状态异常" / "状态未知"
```

**部署要点**：

- 在 Lite3 本机重新编译 `realtime_gauge.cpp`。**当前尚未编译，为 Phase 1 最高优先级阻塞项。**
- 编译前确认 Lite3 上 OpenCV 版本（当前二进制文件基于 OpenCV 4.6，版本不匹配需重编）。
- 根据真实光照标定 LAB 红/黄阈值。
- 根据摄像头到仪表距离调整 `minRadius / maxRadius`。
- 将识别结果封装为 ROS2 节点或独立进程，通过话题输出。

### 5.2 区域字母识别

**新增模块**：`letter_detector`

因 `src/detect` 暂无字母识别能力，需新增一个轻量节点。**已确认采用模板匹配方案**。

**实现思路**：

1. 在图像中定位配电柜 A4 纸区域（白色背景、黑色字母）。
2. 对候选区域进行二值化、透视校正、缩放。
3. 与预存的 A/B/C/D 模板进行相关性匹配，取最高得分。
4. 连续 N 帧一致才视为稳定识别。

**输入**：单目相机图像 `/camera/image_raw`。

**输出接口**：

```yaml
# /letter/detection
string letter      # "A" / "B" / "C" / "D"
float32 confidence
int32 center_x     # 画面中心 x，用于横向对齐
int32 center_y
float32 depth      # 深度相机测距（可选）
```

**部署要点**：

- 模板需在真实场景下采集或生成，覆盖不同距离、角度、光照。
- 输出字母中心坐标，供视觉伺服使用。
- 连续 N 帧一致才视为稳定识别。
- 若模板匹配准确率不足，再考虑升级为轻量分类模型。

### 5.3 避障感知

**主传感器**：深度相机。

**处理逻辑**：

1. 取深度图中机器人前方扇形区域（例如水平 ±30°，地面以上 10~50cm）。
2. 计算最近障碍物距离 `d_min`。
3. 若 `d_min < 0.8m`，触发避障：向距离较大一侧平移并前进。

**辅助传感器**：尾部超声波。

- 仅在后退或原地转向时启用，防止撞墙。

## 6. 运动控制模块设计

### 6.1 运动驱动

**复用**：[src/test/lite3_ros2_driver_legodom.py](src/test/lite3_ros2_driver_legodom.py)

- 订阅 `/cmd_vel`（Twist）和 `/cmd_gait`（String）。
- 通过 UDP 以 25Hz 发送速度指令，5Hz 发送心跳。
- 接收并发布腿部里程计 `leg_odom2`。

### 6.2 速度规划

| 场景 | `vel_x` (m/s) | `vel_y` (m/s) | `vel_yaw` (rad/s) | 说明 |
|------|---------------|---------------|-------------------|------|
| 巡航 | 0.20 ~ 0.30 | 0 | 0 | 障碍区直行 |
| 搜索 | 0 | 0 | ±0.3 | 原地旋转找柜子 |
| 对齐 | 0.05 ~ 0.10 | 0 | P 控制 | 根据视觉横向误差调整 |
| 避障 | 0.10 | ±0.20 | 根据深度调整 | 向空旷侧绕行 |
| 识别 | 0 | 0 | 0 | 停稳后识别 |

**约束**：

- `vel_x` 限制在 `[-1.0, 1.0]` 内，实际使用 0.3 以下。
- `vel_y` 限制在 `[-0.5, 0.5]` 内，实际使用 0.2 以下。
- `vel_yaw` 限制在 `[-1.5, 1.5]` 内，实际使用 0.5 以下。

### 6.3 步态规划

复用 `GAIT_CMDS`：

| 步态 | 指令码 | 使用场景 |
|------|--------|----------|
| `medium` | `0x21010307` | 常规巡航 |
| `stair` | `0x21010407` | 穿越障碍区，增强越障 |
| `slow` | `0x21010300` | 精细对齐、识别 |
| `crawl` | `0x21010406` | 需要降低重心时 |

## 7. 语音播报模块设计

### 7.1 硬件

- USB 免驱扬声器。
- Jetson Xavier NX 识别为默认音频输出设备。

### 7.2 软件

新增 `voice_broadcast_node`：

- 订阅 `/voice/play`（String）。
- 收到文本后调用系统 TTS 或播放预录音频。

**推荐实现**：

```python
# 方案 A：使用 pyttsx3（离线 TTS）
import pyttsx3
engine = pyttsx3.init()
engine.say(text)
engine.runAndWait()

# 方案 B：预录音频 + aplay
import subprocess
subprocess.run(["aplay", f"audio/{letter}_{status}.wav"])
```

**建议**：赛前预录所有组合音频（A-正常、A-偏高、A-偏低、B-正常……共 12 段），比赛时用 `aplay` 播放，避免 TTS 延迟和依赖问题。

### 7.3 播报内容规范

依据赛题示例，播报格式：

```
"{字母}区域仪表盘{状态}"
```

例如：

- "A 区域仪表盘正常"
- "B 区域仪表盘偏低，状态异常"
- "C 区域仪表盘偏高，状态异常"

## 10. 错误处理与安全机制

### 10.1 异常监控

| 异常 | 检测方式 | 处理 |
|------|----------|------|
| 视觉丢失 | 连续 10 帧未检测到圆盘或字母 | 停止移动，原地小范围搜索 |
| 避障失效 | 深度最小距离持续减小 | 立即停止，后退，尝试另一侧 |
| 速度指令超时 | 状态机 1s 未更新 cmd_vel | 自动发送零速度 |
| 里程计漂移 | 与预期距离偏差过大 | 不完全依赖里程计，以视觉触发为主 |
| 摔倒/失控 | 速度反馈与指令长期不符 | 进入 `EMERGENCY_STOP` |
| 心跳丢失 | 运动主机未收到心跳 | 驱动节点自动重发，退出前切手动 |

### 10.2 安全退出

任何异常退出必须执行：

1. `vel_x = vel_y = vel_yaw = 0`。
2. 切换手动模式（`0x21010C02`）。
3. 发送趴下指令（`0x21010202`）。
4. 关闭 UDP socket。

### 10.3 紧急停止条件

触发 `EMERGENCY_STOP` 的条件：

- 深度相机检测到前方 0.3m 内有障碍且速度未降为零。
- 检测到机械狗姿态异常（如有 IMU 数据）。
- 人工通过服务调用 `/mission/emergency_stop`。
- 状态机运行超过 5 分钟（单轮超时保护）。

## 13. 风险与对策

| 风险 | 影响 | 可能性 | 对策 |
